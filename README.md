## Claude API 余额不足时，会发生什么

先说结论：不会产生天价账单，但服务会直接停。

Anthropic 采用预付额度制，调用只从已购买的额度里扣。几条规则值得记住：

- 只为成功的调用和已完成的任务付费，失败的请求不计费。
- 有一个例外：如果请求本身“本来会成功”，但客户端中途断开或超时，这笔钱照扣。跑长任务时尤其要注意。
- 额度一旦用尽，充值之前 API 和 Playground 都无法使用。

还有一点容易忽略：购买额度的覆盖面包括 API、Playground 和编程代理（the coding agent）。也就是说，在 Playground 里反复调试提示词，花的也是同一笔钱。余额消耗比预期快，先检查是不是这几个入口都在用。

判断余额状况不复杂：打开 Console 的计费页面，可用余额和消耗明细都在那里。与其等报错，不如养成看一眼的习惯。

## 先分清你花的是哪笔钱

很多人搞不清一件基础的事：claude.ai 的聊天订阅和 Claude API 是两套完全独立的计费。订了 Pro 不代表 API 有钱，API 花光也不影响网页聊天。

现在你的钱实际上分三个池子：

1. **套餐自带用量**：Pro/Max 订阅里包含的聊天和编程代理使用量，按会话和每周限额走，跟 API 无关。
2. **月度 API 赠送额度**：Max 和 Team 订阅的较新福利，每月发放，但需要手动领取，下面细说。
3. **自购预付额度**：在 Console 里充值的钱，按成功调用扣。

把这三笔钱混着看，就容易出现“我明明订了 Max，API 怎么还是余额不足”的困惑——原因多半是赠送额度从来没人去领。不领，等于没有。

## 官方充值：Console 里的完整流程

### 手动购买额度

步骤很短：

1. 用管理员或计费角色的账号登录 Console；
2. 进入设置里的计费页面；
3. 点“购买额度”，输入金额，确认。

买完立即可用。如果账号没有管理员或计费权限，先找组织里有权限的人操作。

### 设置自动充值，避免再次断粮

长期稳定调 API 的话，手动充值迟早会忘。自动充值解决的就是这个问题：余额低于你设定的阈值时，系统自动按你设定的金额买一笔新额度。

设置入口在计费页面的自动充值区域，点编辑，打开开关，填两个数：触发购买的最低余额、每次充值的金额。比如余额低于 $10 就自动充 $50，按自己的消耗速度定就行。

### 有效期和退款：买之前先知道

- 额度自购买之日起**一年内有效**，过期日不能延长。
- **所有额度购买不可退款。**
- 过期的额度会出现在计费页面的发票历史里。

这两条决定了充值策略：不建议一次囤太多。按两三个月的用量买，配合自动充值，比囤一大笔然后看着它过期划算。

领取路径：登录 claude.ai，进入设置 → 计费 → API credits 区域，把你的计划关联到一个 Claude Console 组织。还没有组织就当场创建一个，个人身份也可以。两个细节要注意：

- **不关联就领不到。** 就算页面弹过提醒，没去设置页完成关联，额度就一直躺在那里。

## 常见问题

**失败的请求扣钱吗？**

不扣。计费只针对成功的调用和已完成的任务。但“本来会成功”的请求如果中途断线或超时，仍会计费。

**额度过期能退吗？**

不能。购买额度一年过期，不能延期，也不退款。过期记录在发票历史里可以查到。

**月度赠送额度和自购额度，先扣哪个？**

先扣赠送的。两者都有的时候，看到余额下降先确认是哪笔在消耗，避免误判。

**订了 Max，为什么 API 还是余额不足？**

三种可能：还没在 claude.ai 设置里关联 Console 组织（不领等于没有）；你用的是交互式编程代理，而赠送额度不覆盖它；当月赠送额度已经用完，又没开自动充值。

**充值有最低金额吗？**

官方帮助文档没有写统一的门槛，有国内教程提到 $5 起充，以 Console 支付页实际显示为准。

**完全没有海外卡，最省事的路线是什么？**

看需求。只想用编程代理写代码，美区 Apple ID 订 Pro 是成本更低的路；确实要调 API，就在靠谱的第三方渠道里选一个，付款时把优惠码用上。
